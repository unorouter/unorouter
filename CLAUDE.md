Next.js 16 AI chat app. React 19 compiler, Tailwind v4, shadcn/ui. Elysia BFF in front of an upstream `new-api` service. Local-first: a per-user SQLocal/OPFS DB in the browser is the SOLE source of truth for chat/RP state. The Turso mirror sync was removed and its dormant `sync_expires_at` columns were dropped; the server DB (Turso) now holds ONLY the model-tester rankings tables. Cross-device transfer is via local export/import only.

## Commands

```bash
bun dev:log          # dev server (logs to /tmp/next.log)
bun build            # production build. prebuild: search index + bundled migrations. postbuild: openapi refs
bun lint             # eslint
bun prettier         # format the repo
bun openapi          # regenerate openapi.ts from upstream spec (Orval)
bun db:generate      # drizzle-kit generate (server + client configs) then bundle migrations
```

Scripts in `scripts/`: `generate-search-index.ts` (Orama index from registry), `bundle-migrations.ts` (writes `src/lib/db/client/schema-migrate/migrations.json`), `generate-openapi-refs.ts` (writes `.next/.openapi-types/references.json`), `generate-web-bot-auth-key.ts` (mints `WEB_BOT_AUTH_PUBLIC_JWKS` + `WEB_BOT_AUTH_PRIVATE_JWK` env values), `indexnow.ts` (IndexNow URL submission), `lighthouse.ts`.

Drizzle outputs: `drizzle/server/` (Turso migrations + meta), `drizzle/client/` (SQLocal migrations + meta consumed by `bundle-migrations.ts` -> `migrations.json` -> runtime `runMigrations`).

NEVER start, restart, or kill the dev server. Read `/tmp/next.log` for errors. Use browser MCP to inspect.

NEVER run `bun run build` (or `rm -rf .next`) inside this repo while the dev server may be running. Dev and build share the single-writer turbopack persistent cache in `.next/cache`; a concurrent build corrupts it ("Persisting failed: Unable to write SST file", "Another write batch or compaction is already active") and deleting `.next` kills the live dev server outright (ENOENT manifests, MODULE_NOT_FOUND runtime chunks, every route 500s until the user restarts it). Verify production builds in a detached git worktree instead:

```bash
git worktree add /tmp/uno-build HEAD && cd /tmp/uno-build && bun install && bun run build
git worktree remove --force /tmp/uno-build   # when done
```

## Architecture

BFF in front of upstream `new-api`. Most server routes are thin typed pass-throughs via Orval-generated clients. `ai/chat` owns real local logic. RP entities are 100% client-side against SQLocal (no server route surface, no mirror); the `/sync` route + mirror stack were removed.

Dependency direction (keep it one-way; do not create back-edges): `route.ts` (validate + delegate) -> `*.service.ts` (domain logic) -> db/data layer. Routes never hold domain logic; services never import routes. The isomorphic chat engine (`src/lib/ai/chat/`) is PURE of server-secret/data-source access - everything that touches a token, Tavily, embeddings, or model pricing is injected via the `AssemblerDeps` seam (`pipeline/deps.ts`), so the same code runs in the browser (both text paths) and is reused server-side for title/media. `src/lib/ai/providers/` + `src/lib/ai/agents/` are leaf modules: they import types + the freeModelRace/inlay primitives, never routes or React.

Server routes grouped into 5 domains under `src/server/`:

- `ai/`: `chat/` (streaming + prompt assembly), `character-cards/` (import proxy)
- `auth/`: `account/`, `settings/`, `web-bot-auth/`
- `billing/`: `core/`, `affiliate/`, `dashboard/`, `token/`
- `models/`: `model-status/`, `perf-metrics/`, `pricing/`, `rankings/`
- `ops/`: `badge/` (Satori SVG), `health/`, `logs/`, `stats/`

`src/server/constants.ts` holds `getUserId/getApiKey/getProvider/deriveUpstream/ADMIN_HEADERS` (`getProvider(apiKey, BodyMutations)` wraps fetch with per-model body rewrites: Anthropic `cache_control`, deepseek prefix/thinking, claude adaptive thinking). Chat/title key resolution is `resolveChatApiKey` in `src/server/billing/token/best-key.service.ts` (client-store cookie -> best-key upstream lookup via the user's own access_token -> `serverEnv.guestApiKey` -> throw). `src/server/env.ts` reads + validates required env vars; fails fast at module load when `SYSTEM_ACCESS_TOKEN` or `SESSION_SECRET` is missing or `SESSION_SECRET` is too short (< 32 chars).

- BFF entrypoint (`src/app/api/[[...route]]/route.ts`, Elysia): mount order = openapi plugin, then `webBotAuthPlugin` (populates `verifiedAgent`), then 5 domain routes. No requestId/timing/error middleware at root; `x-request-id` is forwarded by `deriveUpstream` when the caller supplies it. Openapi root carries MPP `x-service-info` annotations.
- Upstream client: `src/openapi.ts` (Orval-generated, ~17k LOC, never edit). Mutator `src/lib/custom-fetch.ts`.
- Two DBs, both Drizzle ORM / SQLite dialect:
  - Server: Turso/libSQL. `src/lib/db/server/client.ts` `getDb()` (STAYS; the model-tester needs it). Lazy. First call runs `migrate()` fire-and-forget (skipped when `serverEnv.standalone`); the boot migrate WARNs (not errors) on a write-blocked/read-only Turso. First request can race a cold-start migration.
  - Client: sqlocal's client over SQLite WASM's **opfs-sahpool** VFS (no COOP/COEP, no SharedArrayBuffer). `newSql` (`src/lib/db/client/new-sql.ts`) injects an app-owned worker (`sahpool/sahpool-worker.ts` hosting `sahpool/sqlite-sahpool-driver.ts`, written in sqlocal's driver style for upstreaming) via sqlocal's public `processor` config. One pool per database path in its own OPFS directory (`sahpool/pool-name.ts` for naming); logical filenames inside a pool are absolute. `src/lib/db/client/client.ts` `getLocalDb(userId)` = per-userId promise cache + `LocalClient` wiring; per-user logical file `${appName}-${userId}.sqlite3`. LEGACY MIGRATION: while a plain pre-sahpool sqlite file exists at the OPFS root, `migrateLegacySqliteFile` stream-imports it into the pool, integrity-checks, re-runs migrations, then moves it aside to `.pre-sahpool` (rollback copy) - idempotent because pool import is a wholesale overwrite. Safari has no main-thread `FileSystemFileHandle.move()`, so that path COPIES the bytes via `createWritable` before removing the original; only if the copy itself fails is the legacy file removed without a rollback (it cannot be kept: the next open would re-import it wholesale and discard everything written since). ORPHANED-POOL GUARD (`assertNotSilentlyEmptied`): opfs-sahpool verifies a digest in each pool file's 4096-byte header on every install and, when it fails, SILENTLY drops that file's logical name and frees the slot, so the next open creates an empty database under the same name and the app looks wiped (a torn header is what an abrupt iOS Safari tab kill mid-header-write produces; one user lost a long RP this way). After migrations, an EMPTY database whose pool still contains a STRICTLY LARGER sqlite file throws a non-recoverable `OpfsSAHPool orphan` error (explicitly excluded from `isRecoverable`, else the retry loop would re-open the same empty replacement and report success) - the user gets the DB-unavailable state with their bytes intact, and `sahpool/salvage.ts` + the Local DB Studio "recover" action read past the header to extract the orphaned database as a downloadable file for re-import. `openMigratedSql` NEVER blind-wipes: on a recoverable open error (`isRecoverable`; a second live tab's pool-install failure is refused as in-memory and synthesized into this) it retries the open with capped backoff (7 tries, ~4.5s) leaving files untouched; non-recoverable errors rethrow. The per-statement `run` wrapper reopens+replays once on a recoverable mid-session failure (single-flight reopen), no reload needed. MULTI-TAB: one tab OWNS a pool at a time (single-writer, so no torn headers), but ownership moves ON DEMAND via cooperative handover (`sahpool/db-ownership.ts` BroadcastChannel `want` protocol + waiting Web Lock acquire in `outbox/resource-lock.ts`): a contending open broadcasts `want` (re-sent every 2s; a one-shot is lost when the owner has not finished its own open) and waits in the lock queue up to 15s; the owner drains in-flight statements, pauses its VFS (driver `pause()` = closeDb + `pauseVfs()`, releasing every sync access handle; `resume()` = `unpauseVfs()` + reopen; posted as `sahpool-pause`/`sahpool-resume` control messages the worker intercepts before `SQLocalProcessor`, RPC helpers `pauseSql`/`resumeSql` in `new-sql.ts`), releases the lock, and the requester is granted. A parked tab's next statement steals ownership back the same way (every statement path in `client.ts` gates through `ensureOwned`); a 2s minimum hold stops per-statement ping-pong. Only a hung owner (15s timeout) still surfaces the DB-unavailable state (`TAB_LOCK_MARKER`, kept non-recoverable as the backstop).
  - Shared schema: `src/lib/db/schema/` (`shared.ts` = both, `client.ts` = client-only, `rows.ts` = canonical `$inferSelect` row types, `index.ts` = server build entrypoint, now `export * from "./shared"` only).
- Client state: Jotai (cookie-persistence via `atomWithStorage` + `jotaiCookieStorage`). Plus an in-memory `chatStore = createStore()` exposed for non-React callers.
- URL search-param state: nuqs (`NuqsAdapter` in the root `src/app/layout.tsx`; `useQueryState` + `parseAsStringLiteral(...).withDefault(...)` - defaults are elided from the URL via clearOnDefault). Used by model-detail tabs/window/period, rankings period, logs tab. Never hand-roll `useSearchParams` + `router.replace` for filter state (static-shell bailout + an RSC round-trip per change). The /models browse page bridges nuqs <-> the cookie-persisted jotai filter store at the STORE level (`ModelsUrlSync` in `use-models-url-sync.ts`: `useQueryStates` owns the URL, `store.sub`/`store.set` own the state), because atomWithStorage's cookie hydration lands after the first commit's subscribers register and its notify does not reliably reach them - the bridge subscribes the base atom directly, seeds mount-time URL params into still-default fields (cookie beats a stale link), then does a reset-to-INITIAL + set pair one tick later so every subscriber re-renders with the final state.

The route is `force-dynamic` + `revalidate: 0` (the factory's default `force-static` makes Next emit `s-maxage=1yr`, which once poisoned the Cloudflare edge cache un-purgeably; hence force-dynamic + a `no-cache` header on `/sw-worker/*` in both `next.config.ts` and `proxy.ts`, and the path moved off the poisoned `/serwist/`). `next.config.ts` wraps with `withSerwist` (marks esbuild as a server-external package). Registered manually by `src/components/provider/app/sw-register.tsx` at `/sw-worker/sw.js` scope `/` (route sets `Service-Worker-Allowed: /`), mounted in `[locale]/layout.tsx`, prod-only. `proxy.ts` has an early `/sw-worker/` bypass (skips next-intl locale rewrite, adds no-cache). Every runtime matcher is gated on `sameOrigin` (cache-correctness: never cache opaque third-party responses); `/api/*` + `/sqlocal/*` are `NetworkOnly`; navigations are `NetworkFirst` with NO networkTimeoutSeconds (a timeout served the PREVIOUS build's HTML on slow links, 404ing its chunks after deploys and killing all event handlers) and `/en/offline` (`src/app/[locale]/offline/page.tsx`, static, no auth/SQLocal; registered in `routing.ts` pathnames + privateRoutes) as the document fallback. The serwist glob only covers `_next` static output + `public/`, NOT rendered app-route HTML, so `/en/offline` is precached explicitly via `additionalPrecacheEntries` in the sw-worker route (revision = `.next/BUILD_ID`); without it the fallback never matches and offline navigations reject with no-response. Manifest (`[locale]/manifest.webmanifest`) + icons + `metadata.ts` wiring predate this. Build-scoped runtime caches (`pages`, `pages-rsc`, `pages-rsc-prefetch`, `others`) are wiped in the SW `activate` handler so a new deploy can never mix cached HTML/RSC from an old build with new chunks. Works offline for guests + logged-in (local-first reads need no network).

## Route return conventions

Two patterns, pick by domain:

- Pass-through routes (`auth`, most of `billing`, `models`, `ops/logs`, `ops/stats`, `models/*`): `return unwrap(res)`. Upstream response shape flows through.
- Local-logic routes (`ai/chat`, `ops/health`, `ops/stats`): `return { success: true, data }`. Wrapping is needed so `handleElysia()` on the client can distinguish success from typed failure.

Stick to the pattern of the route you're editing. Don't mix.

## Rules

- No prop destructuring in function signatures. Use `props.field`. Exceptions: spreading, defaults.
- Full translation keys with UPPER_SNAKE nesting: `t("BILLING.CURRENT_BALANCE")`. Use `msg()` for non-React code.
- Real translations in every locale file. Never English placeholders. Chinese files use full-width punctuation.
- Query keys from `src/lib/react-query/keys.ts` only. Never raw string arrays.
- ANY query whose `queryFn` reads the local SQLocal DB MUST append `userId` to its key: `queryKey: [...queryKeys.foo(), userId]` (the `makeRpEntity` factory already does this). `localUserIdAtom` resolves its cookie AFTER mount, so the first render runs as `GUEST_USER_ID`; without the id in the key that empty guest result is cached under the same key and `staleTime: Infinity` serves it forever, so the user's own data never appears until something else forces a refetch. This shipped as a real bug (image history looked empty until you edited a form field). Invalidation is prefix-based, so appending the id does not break existing `invalidateQueries` calls.
- After a mutation writes the local DB, `invalidateQueries` so the affected queries refetch from it. No network round-trip, so no need for `setQueryData` cache patches or optimistic rollback.
- No `useMemo` or `useCallback`. React 19 compiler handles memoization.
- No dashes as punctuation (em, en, `--`). Rephrase.
- Named exports for components. `"use client"` at the top of client components.
- Kebab-case file names. Suffixes: `*.service.ts`, `route.ts`, `*-hook.ts`, `*-store.ts`, `*-adapter.ts`.
- Client local-DB functions accept `userId?: number` (or `number | undefined` when a required param follows), defaulting to `GUEST_USER_ID`. Hooks resolve the server-injected `localUserIdAtom` (via `useLocalUserId()`) to a concrete id; guest and user DBs are separate OPFS files. Never the magic literal `0`.
- Dates via `dayjs` (shared singleton, `src/lib/utils/format/date.ts`; plugins extended once at server entry via `instrumentation.ts` and once at client entry via root layout). Never raw `Date` or `toLocaleDateString`.
- Enum-like types use a TypeBox `t.Union([t.Literal(...)])` plus a derived type. No new TS `enum` keyword anywhere. The only TS `enum` block lives in `src/lib/types/enums.ts` (`StoreId/ModelTypeFilter/Vendor/OS/DataTableId`) and is grandfathered; don't add to it.
- Drizzle text columns narrow via `.$type<>()` from those validation-derived literal-union types.
- Never refactor files directly under `src/components/ui/` for conciseness (no splitting, no compression passes). This rule covers ONLY that exact path (its shadcn/assistant-ui derived primitives), not other `ui/` folders elsewhere in the tree. Those primitives stay as-is; only touch them for real bug fixes or requested features.
- No `sql.transaction()` wrappers in client SQLocal code. The transactionMutex deadlocks every later DB call if any statement throws. Use bare exec loops + `ON CONFLICT DO NOTHING` / `INSERT OR IGNORE` (see `replaceChildRows`, `runMigrations`, `reconcileImport`).

## Key patterns

Elysia routes (`src/server/<domain>/<feature>/route.ts`): validate with TypeBox (`body:` / `query:` / `params:`), derive upstream headers with `.derive(deriveUpstream)`, call either the Orval client (pass-throughs) or a local `*.service.ts` (chat/billing). No try/catch in route handlers.

Hooks (`src/hooks/`): feature-grouped into `ai/`, `auth/`, `billing/`, `models/`, `ops/`, `ui/`. Mutations call Eden Treaty, unwrap with `handleElysia()`, use `handleError(e, t)` in `onError` for i18n toasts.

`makeRpEntity` (`src/hooks/ai/rp/factory.ts`): generic `<TItem, TCreateBody, TUpdateBody>` that emits `{useList, useItem, useCreate, useUpdate, useDelete, useDuplicate}`. Each mutation writes the local SQLocal DB and invalidates list/item keys (no Turso mirror). The single source of CRUD for characters/personas/lorebooks/presets/cards. `useDuplicate` (RisuAI parity) clones an entity by id into a fresh id with the name suffixed ` {RP.COPY_SUFFIX}`; entities with child rows pass a `cloneEntity` opt to re-id them (lorebooks deep-copy their entries). The shared `RpEntityRow` (`rp/shared/rp-list-parts.tsx`) renders the duplicate button when an `onDuplicate` prop is passed.

`src/lib/db/client/data/` is grouped by domain: `chat/` (chat, chat-context, request-log, queued-send), `rp/` (rp, rp-export, custom-providers), `tester/`, `media/` (media, inlay-render, tokenizers), `diagnostics/` (diagnostics, db-export), `transfer/` (conversation export/import). Shared primitives stay at `data/` root (`table-store.ts`, `theme.ts`); the SQLocalDrizzle factory `newSql` is `src/lib/db/client/new-sql.ts`.

`makeTableStore` (`src/lib/db/client/data/table-store.ts`): Drizzle wrapper emitting `{list, get, upsert, drop}` for any SQLocal table. `scopeUser` toggle ANDs `eq(table.userId, uid)` into WHERE and merges userId into upsert rows; tables without a `userId` column (`messages`, `lorebookEntries`, etc.) pass `scopeUser: false`.

`replaceChildRows` (`src/lib/db/client/data/table-store.ts:28`): FK-scoped delete + insert loop. NO transaction wrapper. `mergeChildRows` (same file, line 57) is the upsert sibling: per-row PK `ON CONFLICT` so existing siblings survive (used on sync-pull of child arrays).

Jotai atoms: `atomWithStorage` plus `jotaiCookieStorage` for cookie persistence. Most store atoms load their cookie asynchronously AFTER mount (no `getOnInit`), so the first client render matches the server-rendered INITIAL state. `chatStoreAtom` is the EXCEPTION and is `getOnInit: true`, PAIRED with `ChatStoreProvider` in the `(chat)` layout, which seeds it from a server-side `getCookieValue(CHAT_STORE_KEY)` read so both renders start from the same values. Both halves are load-bearing: `getOnInit` alone reintroduces the React #418 mismatch on the chat model button (removed for that reason in `8744a119`), and the deferred load alone reintroduces the empty-state window where any write spreads `INITIAL_CHAT_STATE` back over the cookie and silently drops every field it did not name (the provider-pin loss, and the `maxTokens` revert of `1a080093`). `jotaiCookieStorage` is server-guarded because `cookies-next/client` throws off the client and a `getOnInit` atom reads storage during the server render too. Seeding is scoped to `(chat)`: elsewhere these atoms are write-only (`useSetAtom` for "try in chat"), so nothing renders a cookie value outside it. The chat store (`src/store/chat-store.ts`) exposes a shared store instance `chatStore`; non-React callers (stream callbacks, `confirm()`, the `thread.tsx` runtime bridge) read/write atoms synchronously via `chatStore.get(atom)` / `chatStore.set(atom, value)`. Selector atoms fall back to INITIAL state per field (cookie-schema-drift defense). `localUserIdAtom` reads the plain `local-user-id` cookie (unsealed twin of the signed `user-id`, set at the OAuth callback; only selects the local OPFS file, no server trust); `LocalUserIdSync` (`provider/state/local-user-id-sync.tsx`) backfills it from the auth query for pre-twin sessions and resets to guest on logout.

Server pages: prefetch with `getQueryClient()` plus `HydrationBoundary` and `dehydrate()` (layout-level boundaries use `dehydrateOnly` scoped to their own keys so page queries are not re-shipped).

Auth cookies (`src/lib/config/constants.ts` for names; `src/store/client-store.ts` for `CLIENT_STORE_KEY`):

- `access_token`: httpOnly, upstream API token, 30 day TTL. There is NO refresh flow: the fork pins `AccessTokenTTL` to 30d (upstream ships 15min) and `LoginSessionTTL` is also 30d, so token and session expire together and refresh had nothing to renew. Sessions end hard at 30 days and a leaked token stays valid until then. Re-adding revocation means either reverting to upstream's short TTL or checking the session row in auth middleware, NOT restoring the old `/auth/refresh` route. Cookie maxAge tracks the token via `accessTokenMaxAge`; if `AccessTokenTTL` changes in the fork, `ACCESS_TOKEN_FALLBACK_MAX_AGE` must change with it.
- `user-id`: signed via iron-session (`signUserId`/`verifyUserId` in `src/lib/utils/server.ts`), readable by server handlers, used by `getUserId(cookie)` in `src/server/constants.ts`. Requires `SESSION_SECRET` (>= 32 chars).
- `local-user-id`: plain unsealed twin of `user-id`, set alongside it at the OAuth callback. Client-only concern (selects the per-user OPFS file via `localUserIdAtom`); carries no server trust.
- `client-store`: JSON (`CLIENT_STORE_KEY`, owned by `src/store/client-store.ts`), holds the user's own API key (for direct `getApiKey(cookie)` use). Server imports the key constant from the store module.
- Guest users fall back to `serverEnv.guestApiKey` via `resolveChatApiKey(cookie)` (`best-key.service.ts`), which also closes the logged-in-but-cookie-not-yet-hydrated race by resolving the user's best key upstream.

## Type safety pipeline

```
TypeBox schema -> Elysia validation -> Eden Treaty RPC -> handleElysia() -> React Query hook
```

- `handleElysia()` and `unwrap()`: `src/lib/utils/base.ts`

## Chat vertical specifics

The text chat engine is ISOMORPHIC and runs IN THE BROWSER for BOTH paths (assemble + `streamText`): the pure assembly pipeline + prompt + context + trigger code lives under `src/lib/ai/chat/` (5 themed subfolders `pipeline/`, `prompt/`, `context/`, `triggers/`, plus root engines). `src/server/ai/chat/` is now THIN: `route.ts` (token-injecting proxy + small BFF endpoints), media generation, title gen, and the server wiring of those isomorphic engines.

Two text paths, both client-assembled:

- DEFAULT (catalog model): the browser runs the engine, then `streamText` points its `baseURL` at a same-origin thin proxy `POST /api/ai/chat/forward/chat/completions` (`forward.service.ts`). The proxy resolves the upstream token from cookies (NEVER exposed to the browser), enforces the guest free-model gate, strips `group` -> `X-Group`, and RAW-PIPES the SSE to new-api both directions, forwarding the `content-type` + `x-oneapi-request-id` + `x-newapi-dropped-params` response headers (so the client stream collector drives logEnrich + the dropped-params toast). No server assembly, no server `streamText`. Deps from `runtime/default-deps.ts` (`buildDefaultClientDeps`).
- CUSTOM (bring-your-own provider, `custom:::<providerId>:::<modelKey>` id): client-side BY DEFAULT. The browser fires `streamText` DIRECTLY at the user's own endpoint with the user's own token and the server is never involved, UNLESS the provider row sets `proxy` (the "route through UnoRouter" toggle), in which case `resolve-model-target.ts` points `baseURL` at `/api/ai/chat/custom-forward` and moves the real endpoint onto an `x-proxy-target` extra header - the escape hatch for endpoints that serve no CORS headers, which a browser cannot call at all. Provider rows live in the client-only `custom_providers` SQLocal table; deps from `runtime/client-deps.ts` (`buildClientDeps`). Id helpers in `src/lib/ai/chat/custom-provider-id.ts` (`makeCustomModelId`/`parseCustomModelId`/`isCustomModelId`/`normalizeBaseUrl`/`fetchCustomProviderModels`). Each custom model carries a PER-MODEL `tokenizer` (a preset id, `auto`, or `hf:<owner/repo|url>`) used for budget counting; the routing transport passes it on `StreamBody.tokenizer`.

Tokenizers (`src/lib/ai/chat/tokenizer.ts`): per-model token counting for history-fit + lorebook budgeting ONLY (never billing - new-api bills authoritatively), so any load failure falls back to cl100k/char-4 ("approximate") and never throws. Lumiverse-style: tokenizer FILES are NOT bundled. cl100k/o200k via `gpt-tokenizer`, Claude via the `@lenml/tokenizer-claude` package, everything else (glm4/glm5/deepseek/llama3/gemma/cohere/qwen/mistral + any `hf:<slug>`) loads an HF `tokenizer.json` ON DEMAND via `@lenml/tokenizers`, cached in the client-only `tokenizers` SQLocal table (`src/lib/db/client/data/media/tokenizers.ts`). The counters are SYNC (`countTokens`, memoized cyrb53); `prepareChatRequest` PRELOADS the active tokenizer once (`setActiveTokenizer(tokenizerRefForModel(body.tokenizer, body.model))`) before assembly. The DEFAULT (catalog) path always infers from the model name (`inferTokenizerPreset`: glm5/glm4/deepseek/claude/llama3/qwen/... -> cl100k); the custom path uses the per-model pick. Consumers: `pipeline/transforms.ts` (history fit), `prompt/lorebook.ts` (lore budget), `prompt/assembler.service.ts` (prompt size), `triggers/lua/api.ts` (`getTokens`).

Routing lives in `runtime/routing-chat-transport.ts` (`makeRoutingTransport`): media model -> `mediaTransport` (server `/stream`), else -> `sendText` which resolves the model id through `resolveModelTarget` and streams. The shared `runClientStream` assembles + streams identically for both text branches.

`runtime/resolve-model-target.ts` is the SINGLE model-id -> request-target resolver: `resolveModelTarget(modelId, userId, origin)` (pure, testable) returns `{isCustom, model, apiKey, baseURL, deps, tokenizer}` - catalog id -> the `/forward` proxy + `buildDefaultClientDeps`; `custom:::<providerId>:::<modelKey>` -> the user's endpoint + key + `buildClientDeps`. `resolveModelTargetFromStore(modelId)` is the client wrapper (reads `localUserIdAtom` + `window.location.origin`). EVERY caller that needs to reach a model resolves through here: the live transport (`sendText`), `dry-run.ts`, and the illustrator prompt-writer (`illustrator-run.ts`) - so a custom-provider model uses the user's endpoint everywhere, including the in-chat image prompt-writer. (The image goes through our `/trigger-op/imggen` for CATALOG models; custom-provider models flagged `type: "image"` are BYOK image models, dispatched browser-direct to the user's `{base}/images/generations` (or multipart `/images/edits` with refs) via `src/lib/ai/chat/custom-image-gen.ts` - the branch lives in `requestImggen` in `illustrator-run.ts`. Image-typed custom models are excluded from the chat model dropdown and merged into the illustrator's image picker instead.) Previously this custom/catalog branch was copy-pasted across those 3 files; the illustrator's copy was custom-blind.

Root (`src/server/ai/chat/`):

- `route.ts`: `POST /title`, `POST /stream` (MEDIA ONLY now: image/video/audio/embedding dispatch + guest free-model gate), `POST /forward/chat/completions` (the token-injecting text proxy), `POST /custom-forward/chat/completions` + `GET /custom-forward/models` (the opt-in CORS-bypass pass-through for custom providers whose endpoint sends no `Access-Control-Allow-Origin`, driven by the per-provider `proxy` column; `custom-forward.service.ts` raw-pipes both ways via `safeFetchStream`. NO session required, because BYOK custom providers work for guests: the caller's OWN `Authorization` is mandatory instead, which is what stops it being an anonymous open relay. The target arrives on `x-proxy-target` and passes the standard SSRF policy; only `content-type` is forwarded back, and no key is ever resolved, logged or stored), `POST /web-search` (Tavily BFF; guest -> null), `POST /trigger-op/llm|similarity|imggen` (client-mode V1 lowLevelAccess effects; auth required), `GET /task/:taskId`, `POST /:id/task/finalize`. API keys resolve via `resolveChatApiKey` (`billing/token/best-key.service.ts`: client-store cookie -> best-key upstream lookup -> guest key). No POST/PATCH/DELETE for conversation or messages: those live in client hooks (`src/hooks/ai/chat-hook.ts`) writing the local SQLocal DB.
- `forward.service.ts`: `forwardChatCompletions` - the token-injecting SSE proxy described above. Just a pipe: no assembly, no streamText, no finish-meta, no body logging/mutation (body mutations were already applied client-side by the `makeBodyMutationFetch` wrapper before the request left the browser).
- `media-stream.service.ts`: `streamMedia` - media-only dispatch (image inline data URLs, video task, audio TTS+STT, embedding). `maxRetries: 2` retries RETRYABLE errors only (429/5xx/network); deterministic 4xx surface verbatim.
- `free-model-race-server.ts`: `serverFreeModelRaceDeps(apiKey)` - the server wiring (getProvider + generateText + catalog free-model list) for the isomorphic `freeModelRace` (used by title gen + web-search classifier).
- `title.service.ts`: stateless title gen via `freeModelRace` (`maxOutputTokens: 30`); strips think-tags (unclosed `<think>` would become the visible title), truncates to ~60 chars on race failure. The client persists.

`src/lib/ai/chat/pipeline/`: the ISOMORPHIC text-request assembly stage (`prepare.service.ts` orchestrates 5 stages under `stages/`). The caller (the client `runClientStream`) owns the `streamText` call; `prepareChatRequest(apiKey, body, userId, deps)` returns a `PreparedChatRequest`. Server-resolved concerns (token, web search, free models, embeddings, model info) come in via an injected `AssemblerDeps` seam (`pipeline/deps.ts`); the default path's deps use OUR services through BFF endpoints, the custom path's use the user's own provider.

- `pipeline/prepare.service.ts`: `prepareChatRequest(apiKey, body, userId, deps, abortSignal?)` + the `PreparedChatRequest`/`StreamBody` types. Thin orchestrator wiring the stages: `stages/resolve-context.ts` (context resolve + web search via `deps.webSearch`), `stages/preprocess.ts` (PDF inline via `deps.inlinePdfText`, regex scripts editprocess/editinput, Lua editinput), `stages/assemble-prompt.ts` (start triggers, memory, prompt assembly, output-cap clamp, history budgeting, depth splice, macro expand), `stages/role-transform.ts` (template walk + system hoist + the ORDER-LOCKED role transforms + Lua editrequest + #escape un-map), `stages/build-body.ts` (modelParams, providerOptions, bodyMutations, var writebacks, request-log snapshot, cost estimator via `deps.getModelInfo`). CANCELLATION: the optional `abortSignal` (the same one `runClientStream` passes to `streamText`) is checked at each stage boundary via `throwIfAborted`, so a user abort during a slow tokenizer download / heavy lorebook scan stops assembly promptly instead of only being honored once streaming starts.
- `pipeline/finish-meta.ts`: `createMetaCollector` (captures `x-oneapi-request-id` + `x-newapi-dropped-params` off the `finish-step` response headers client-side), `makeBuildUsage`, `buildFinishMeta`. The ONE finish-meta builder both text branches emit on the `finish` part via `messageMetadata`: token usage + cost + writebacks (vars/globalVars/summary) + speaker tag + the request-log debug snapshot. The client persists the request-log row LOCALLY at stream finish, then enqueues a `logEnrich` pending task to overwrite the estimate with new-api's authoritative cost/tokens/channel (`GET /ops/logs/by-request`).
- `pipeline/provider-mutations.ts` (`src/lib/ai/chat/`): pure `makeBodyMutationFetch`/`applyCacheControl`/`hasBodyMutation`/`BodyMutations`. Anthropic prompt caching + deepseek prefix/thinking + claude adaptive thinking apply CLIENT-SIDE via the `fetch` wrapper on the openai-compatible provider, rewriting the JSON body before it leaves the browser (the proxy does NOT re-apply them).
- `pipeline/transforms.ts`: pure message ops (PDF inline, depth splicing, macro expansion, role transforms, failed-turn drop, reasoning/think-tag strip, token budgeting, gemini safety). Free models capped at `FREE_MODEL_OUTPUT_CAP=8192`; unknown model caps fall back to `UNKNOWN_MODEL_OUTPUT_CAP=4096` (clamp in `stages/assemble-prompt.ts`). PDF parts get inlined as text from `media.extractedText`; missing extraction inserts a placeholder (no throw). Isomorphic PDF extraction in `src/lib/ai/chat/pdf-extract.ts` (`inlinePdfText`/`extractPdfText`, lazy `import("unpdf")`).
- `pipeline/role-flags.ts`: now a THIN SHIM over the provider adapter layer (`src/lib/ai/providers/`). `getModelRoleFlags(model)` = `resolveAdapter(model).roleFlags`; re-exports the `ModelRoleFlags` type. The per-model flag DATA + model-name matching moved into one self-contained adapter module per family (`providers/{deepseek,glm,gemini,claude,openai}.ts`), registered in `providers/registry.ts` as an ORDERED list (first match wins, mirroring the old RULES order: deepseek before glm; gemini-thinking before gemini; claude opus-5 before 4.x/5 before legacy; unknown -> `DEFAULT_ADAPTER`). Adding a provider family = add an adapter module + register it, no central table edit. Each adapter also carries a declarative `ProviderCapabilities` descriptor (`providers/types.ts`) for future UI/validation use (not yet consumed by the pipeline). Role flags OR with the preset's manual flags; a manual flag is never silently turned off. The request-mutation flags (`deepSeekPrefix`/`deepSeekThinkingToggle`/`deepSeekThinkingInput`, `claudeAdaptiveThinking`/`claudeXHighEffort`, `noCivilIntegrity` = gemini thinking-exp drops CIVIC_INTEGRITY, `cacheControl` = Anthropic cache injector gate) are still part of `ModelRoleFlags`; `stages/build-body.ts` `buildBodyMutations`/`buildProviderOptions` consume them generically (flag-driven, NOT provider-branching, so they stay in build-body) and map them to `bodyMutations` applied by `makeBodyMutationFetch`. o-series system->developer + max_completion_tokens renames are upstream new-api's job, never re-mapped here.
- The context source is ALWAYS the client (the browser is the source of truth); there is NO server context cache, no FNV-1a dedup handshake, and no 409 `context-required` retry anymore (the old `context-cache.ts` + Turso `loadConvContext` fallback were removed when the engine moved client-side).
- Message-shape pipeline lives in `src/lib/ai/chat/messages.ts` (`partsToItems`/`itemsToParts`). Maps ai-sdk `tool-invocation` (state-based: call vs result) to typed DB rows `tool_call`/`tool_result`. `data-task` part bidirectional with `task` DB type. `file` and `source-url` map to `file`/`image`. `error` items (failed run persisted as a branch node, partial text kept) render as `data-error` parts; the WHOLE assistant turn is dropped from request history by `dropFailedAssistantTurns` (the partial text is a truncated reply, and sending it back made the model treat the fragment as canon and remark on the broken story). Editing such a turn clears the `data-error` part, since a rewrite is how a user repairs a failed generation. Offline failures persist no node (queued semantics).

`src/lib/ai/chat/prompt/`: prompt-assembly pieces the pipeline composes.

- `prompt/assembler.service.ts`: `assembleForStream` + `assembleFromOverrides` + `AssembledSystem`. Reads `prompt/conv-context.ts` (`buildContextFromClient`), `prompt/lorebook.ts` (`keyHits`, `selectLorebookEntries`, `parseDecorators`), `prompt/example-messages.ts` (few-shot turn parsing). Default order: `main_prompt -> system_fallback -> lorebook entries (single slot) -> per-character blocks -> persona -> systemPromptOverride||primary.systemPrompt -> example-message few-shot turns -> [chat history] -> postHistoryInstructions + preset.postHistory`. Lorebooks have NO position concept: every selected entry is its own role-tagged message in the one `lorebook` slot, ordered by `orderIndex` then `priority`. Only `authorNote` still returns as a `DepthInjection` spliced by `spliceDepthInjections`. Multi-character: primary drives `{{char}}` (the speaking character floats to primary per turn); non-primary chars with `alwaysActive=false` are gated via `turnTriggers` + `matchWholeWords`. `extraBody` from settings beats preset on key clash; sliders + reasoning then win over both in providerOptions.
- Lorebook selection (`prompt/lorebook.ts`): SINGLE GLOBAL POOL (RisuAI fullLore): one priority ranking under one shared token budget (max of book budgets, counted via the active per-model tokenizer), one recursion namespace (`MAX_RECURSIVE_LOREBOOK_PASSES=3` when any book has `recursiveScanning`); per-book `scanDepth` applies to matching only; scans user AND assistant history. RisuAI/CCardLib `@@decorator` lines parsed from entry content: `@@probability` (seeded per turn), `@@scan_depth`, `@@order`/`@@insertorder` + `@@priority` overrides, `@@role`, `@@activate_only_after/every`, sticky `@@keep/dont_activate_after_match` (state persisted in conversation vars), `@@inject_*` lore-into-lore, recursion flags (placement/depth decorators are gone with the single-slot model). Single lorebook slot, sorted `orderIndex` DESC (higher = earlier) -> `priority` DESC -> entry id; one role-tagged message per entry. Each entry also has a `comment` column (ST/Risu non-AI display name): shown as the entry's title in the editor list, round-tripped on ST/CCv3 import/export, NEVER sent to the model (the assembler reads only `content`/`keys`).
- `prompt/template.ts`: RisuAI prompt template, user-orderable card array (`slot` | `plain` | `chat` history marker with ranges) stored as preset `promptTemplate` JSON; `DEFAULT_PROMPT_TEMPLATE` reproduces the fixed order so the no-template path is byte-identical. The role-transform stage hoists the leading system run into the `system` param (skipped under noSystemRole so char data isn't silently dropped).
- CBS macro engine lives in `src/lib/ai/chat/macros.ts` (isomorphic, NOT under this folder, so the client can expand greetings). Full RisuAI port: field tokens, seeded roll/random/pick stable across regenerates, calc RPN, string/array/dict ops, conversation/global/temp vars, history readers, per-message time/date macros (client sends `messageTimes` + `clientEnv` viewport/locale/timeZone on the stream body, OUTSIDE the hashed context), block forms `{{#if}}`/`{{#if_pure}}`/`{{#when}}` (line-based else, dead branch still expands like Risu)/`{{#each}}` (slot substitution, `§` arrays)/`{{#pure}}`/`{{#puredisplay}}`/`{{#escape}}` (private-use char mapping, un-mapped by `unescapeMessages`/`risuUnescape` at request build), `{{// comment}}`, `{{? calc}}`, `{{return}}` abort. Any `{{/...}}` closes the innermost block (Risu stack semantics). App-coupled macros resolve to safe empties. Var writes mutate the scope in place and ride back via finish-meta writebacks (`vars`, `globalVars`).

`src/lib/ai/agents/`: agent pipeline (Marinara-style) - the abstraction for BUILT-IN chat behaviors that run an auxiliary LLM call around the main generation. Distinct from the Risu trigger VM (`triggers/`, the USER-authored scripting surface). `types.ts` = the contract: `AgentDefinition` (`{id, phase, capabilities, enabled, run}`), `AgentContext` (recentMessages oldest-first, mainResponse set only in post*processing), `AgentRuntime` (injected LLM caps: listFreeModels/generate = freeModelRace primitives, optional generateImage = inlay), `AgentResult` (`context_injection`/`inlay_image`/`summary`/`noop`). CAPABILITY GATE: every agent declares `capabilities: AgentCapability[]` (`inject_context`/`generate_image`/`write_vars`/`write_lorebook`); the runner refuses to APPLY a result whose `RESULT_CAPABILITY` is not declared (gates to noop), so a misconfigured/future agent can't silently corrupt state. `DESTRUCTIVE_CAPABILITIES` (write*\*) is the set that a future approval flow would gate on user sign-off - designed-in now, no contract change needed later. `pipeline.ts` = `createAgentPipeline(agents, baseContext, runtime)` -> `{preGenerate, postGenerate}`; agents in a phase run concurrently via Promise.allSettled, a throwing agent yields `noop`. Each agent owns its own LLM call (Uno races free models, so no Marinara-style provider+model batching). `registry.ts` = `BUILTIN_AGENTS` array; new agent = add `builtin/<id>/agent.ts` + one line. Built-ins: `builtin/summary/` (rolling-summary memory, `inject_context`, wraps `context/memory.service.ts rollSummary`), `builtin/illustrator/` (in-chat image gen, `generate_image`: a second LLM with its own instruction writes an image prompt from ONLY the latest response, then `runtime.generateImage` produces the inlay; result carries the written `prompt`). BOTH ARE WIRED LIVE:

- SUMMARY: `stages/assemble-prompt.ts` `buildMemoryViaAgent` runs the summary agent (pre_generation) for the rolling summary, then the direct `deps.retrieveSemantic` call for the `[Relevant background]` block - producing the same `MemoryContext` the old `buildMemoryContext` did (now removed). Gated on `conversations.memoryEnabled`.
- ILLUSTRATOR: `runtime/illustrator-run.ts` `runIllustrator`, fired ASYNC from `chat-history-adapter.ts append` AFTER the reply persists (never blocks the reply - the async-amend pattern all 3 reference clients use). A `task` message-item with `kind:"image"` is persisted as a placeholder (renders the "generating image" state via `ImagePlaceholder` in `task-card.tsx`); when the image lands the item is rewritten to an `{{inlay::id}}` text item via `replaceLocalMessageItems`. Gated on `conversations.imageEnabled`. The prompt-writer reads the ORIGINAL assistant text (pre regex/Lua mutation). `resolveIllustratorSettings` (same file) is the ONE inheritance resolver (conv override ?? preset default) for `imageEnabled`/`utilityModel`/`promptInstruction`/`imageModel`/`imagePreview`/refs; both the adapter fire and the regenerate dialog use it. Image request features: user-picked `imageModel` (catalog image models, validated server-side, auto-pick fallback), reference images (`conversations.imageRefIds` JSON media-id array uploaded in the overrides drawer via `overrides/image-refs-field.tsx`, plus the primary character's avatar when `useCharAvatarRef` is on; resolved to data: URIs, max 6, server caps by model `maxImageInputs`), and the written prompt persisted on the media row (`media.promptText`). Verify/regenerate UI: `image-prompt-dialog.tsx` + `image-prompt-dialog-store.ts` (pending-request atom, host mounted in `chat-runtime-provider.tsx`): media mode opens from an inlay image's overlay action in `markdown-text.tsx` (the inlay alt text carries `inlay:<mediaId>`) and regenerates IN PLACE (same media id, `invalidateInlay` busts the render cache); review mode is the opt-in `imagePreview` gate (the agent's `reviewPrompt` settings hook pauses between prompt-writing and generation for edit/skip). Prompt-writer style templates live in `src/lib/ai/chat/image-style-templates.ts` (5 instruction presets that FILL the promptInstruction field in the drawer + preset form).
  Both call the UTILITY model (full context), not the small-context free race: `deps.runUtilityLLM` (a `/trigger-op/llm` call with the resolved `conversations.utilityModel ?? chat model`). The free race stays for title gen + web-search classification only. Per-conversation settings `memoryEnabled`/`imageEnabled`/`utilityModel`/`promptInstruction`/`imageModel`/`imagePreview`/`imageRefIds`/`useCharAvatarRef` live on the `conversations` row + `CONVERSATION_SETTINGS_KEYS` (presets carry the same defaults minus `imageRefIds`), toggled in the conversation overrides drawer (`overrides/override-fields.tsx`, gated on `showConversationFields`).

Dry-run (`runtime/dry-run.ts`): `dryRunChatRequest(messages, getConvId)` assembles the FULL prompt the engine would send WITHOUT calling the LLM (no tokens burned), reusing the exact client assembly (`prepareChatRequest` + the same deps/body the live transport builds). Returns `{model, system, messages, debug (the request-log snapshot), stopRequested}` - powers a prompt-inspection drawer and makes the agent migration verifiable (diff the assembled prompt before/after wiring an agent in).

`src/lib/ai/chat/plugins/` is the SANDBOXED USER-JAVASCRIPT surface (global plugins, Risu API V3 model), parallel to the Lua seam rather than part of it. `sandbox-host.ts` is a port of RisuAI's `apiV3/factory.ts` (GPL-3.0, Copyright Kwaroran; combinable into this AGPL work under GPLv3 sec. 13): user code runs in an iframe with `sandbox="allow-scripts"` ONLY, so it lands on an opaque origin with no reach into the DOM, cookies or OPFS, under a CSP whose `connect-src 'none'` means a plugin CANNOT open its own network connections. The only channel is a postMessage RPC carrying callback identity (a handler passed twice is the same function on both sides, so `removeHandler` works), by-reference object proxies (`__classType === "REMOTE_REQUIRED"`), AbortSignal forwarding and MessagePort-bridged streams with credit backpressure. Hardened over the original: user code is escaped before splicing into the script element, the per-request console dumps are gone, and a host with no running frame rejects. `api.ts` is the flat method object the guest calls by name (host answers ONLY names present on it): the Lua binding subset over the same `TriggerContext`, `registerHandler(mode, fn)` for `input|output|request|display`, and `httpRequest` carrying the exact egress policy of the Lua `request` binding (browser-only, https GET, <=120 chars, 5/min). `src/lib/db/schema/shared.ts`: tables defined for both client (SQLocal) + server (Turso). This INCLUDES the model-tester tables `tester_providers/models/tests/probes` (ONE definition, both DBs). The CLIENT holds a user's PRIVATE local test history (real `userId`); the SERVER holds the PUBLIC rankings board, written with `userId = GUEST_USER_ID (0)` so the unique `(userId, kind, host)` key behaves as a global `(kind, host)` key, and gated on `verified_at IS NOT NULL`. The superset `tester_tests` carries client-only (`published_at`) AND server-only (`submitter_user_id`/`submitter_username`/`verified_at` + denormalized `kind`/`base_url_host`/`requested_model`) columns; each side leaves the other's null. Read shapes converge on `TestResultDetail` (`src/lib/api/typebox/model-tester.ts`) so ONE adapter (`toResultCardData`) + ONE list (`result-card-list.tsx`) render history + rankings identically. Per-conversation settings (model, sampling, vars, memory, web search, autoContinue, groupOrderByOrder, firstMsgIndex, ...) live as COLUMNS ON the `conversations` row (the old `conversation_settings` table is folded in; `CONVERSATION_SETTINGS_KEYS` in `src/lib/db/conversation-settings.ts` is the key list). BRANCH-SCOPED VARS: `messages.branch_vars` (nullable JSON) holds the post-turn chat-var snapshot for that branch. Assembly seeds vars from the ACTIVE TIP message's `branchVars` (`buildChatContextFromLocalDb` overrides `settings.vars` with the tip snapshot when present), falling back to `conversations.vars` for pre-branch-vars rows / fresh chats. On persist, an assistant turn's `branchVars` = the stream `varsWriteback` (vars changed this turn) ELSE the PARENT branch's snapshot (carry-forward); user turns inherit the parent's. This isolates sibling swipes - regenerating a turn reads the parent branch's vars, not another swipe's setvar state (fixes the macro-setvar leak across swipes). Known partial: output-mode triggers still write `conversations.vars` directly (the secondary var path); the branchVars snapshot captures the primary assembly-side macro vars (`varsWriteback`). Drizzle `.$type<>()` narrows text columns to validation-derived literal unions (`MessageRole`, `MessageItemType`, `ReasoningEffort`, `WebSearchEngine`, `WebSearchContextSize`, `LorebookInjectionRole`, `UserTheme`).

`src/lib/db/schema/client.ts`: client-only — `js_plugins` (sandboxed user-JS plugins: `script`, `kind` = `uno` | `janitor`, `enabled`; global, not per-conversation), `local_pending_tasks` (PK `(task_type, kind, id)`; outbox driving ONE task today, `logEnrich`; `task_type`/`kind`/`payload`/composite-PK shape is kept so a future per-entity task type can be added without a migration, but the drain in `queue.ts` is currently logEnrich-specific. `MAX_PENDING_ATTEMPTS=5` (`queue.ts`), `EntityKindName` + `PendingSyncOp` + `PendingTaskType` narrowing (unions defined in this file). `kind` stores `""` for tasks without an entity scope), `local_migrations` (one row tracking the last applied migration tag), and `tokenizers` (downloaded HF tokenizer.json cache keyed by `source`, NOT user-scoped - public files shared across users). `LOCAL_ONLY_TABLES` excludes all three from the reconcile-import cross-DB copy (the tokenizer cache just re-downloads on demand).

`media` table: client writes `dataBase64`. Bytes live inline in OPFS (no object storage, no upload); export/import inlines base64 so files travel with the dump.

In-chat image generation (the illustrator/inlay) reuses the isomorphic image-gen engine `src/lib/ai/image/` (`dispatch`/`models`/`models-dynamic`/`constants`/`cost-estimate`) + `submitSyncImage` in `src/server/ai/chat/media/sync-image.ts`, which submits through the shared `src/server/ai/image/upstream.ts` primitives (one post/collect/error path for the image page, the chat inlay and the chat media stream).

`src/lib/db/client/schema-migrate/migrations.ts`: reads the bundled `migrations.json` manifest, enables `PRAGMA foreign_keys = ON`, then runs forward-only from `local_migrations` (the last applied tag). Splits each migration on `--> statement-breakpoint`. NO `sql.transaction()` wrapper (transactionMutex deadlock if any statement throws). After the forward replay, `reconcileSchema` self-heals baseline drift: per table it compares the stored DDL to the manifest and, when they differ, does a SQLite 12-step rebuild (CREATE temp from manifest DDL, `INSERT OR IGNORE` the column intersection, swap, recreate indexes) - but ABORTS the swap and keeps the original table if the rebuild would drop ROWS (NOT NULL/UNIQUE/FK), so a tightened schema never silently loses data. Dropping COLUMNS is intended; dropping rows is not. THEN `validateColumns` is the last-resort safety net (added after a stale OPFS db crashed at query time with a cryptic "no such column"): per manifest table it checks the actual `PRAGMA table_info` against the expected column defs; missing NULLABLE columns are added in place (cheap `ALTER ADD`); a missing REQUIRED column (NOT NULL, no default - which `reconcileSchema` declined to rebuild because its existing rows can't satisfy the tightened schema) triggers `forceRebuildWithDefaults`: a 12-step rebuild that BACKFILLS the missing NOT NULL columns with a synthesized default (explicit DEFAULT, else `0`/`''` by type) so rows survive AND the column exists. Anything still unrepairable is logged loudly with the exact table+columns. Net: a column the live code SELECTs always exists after open, instead of failing as a runtime "no such column".

`src/lib/db/client/data-migrate/reconcile-import.ts` `reconcileImport(userId, buffer)`: powers the Local DB Studio "import" button. NOT a raw byte-overwrite (which adopts the foreign file wholesale, drift and all). CRASH-SAFE: the live file is written EXACTLY ONCE, only after a complete replacement is built, and a byte-identical backup exists on disk until the swap is verified. Phases: (0) snapshot live -> `${app}-${uid}-import-backup.sqlite3` (durable rollback token); (1) overwrite a WORK db (`-import.sqlite3`) with the uploaded bytes + `runMigrations` (forward-migrate the dump to CURRENT schema; `reconcileSchema` fixes drift); (2) build the replacement in a DETACHED `-final.sqlite3` (`runMigrations` for a clean schema, then `copyTable` each shared table work->final over the column intersection with `INSERT OR IGNORE` + before/after skip counting, then graft live-only `local_pending_tasks` + `tokenizers` from the live db, `rewriteUserId=false`); (3) `PRAGMA integrity_check` on final, then a SINGLE `overwriteDatabaseFile(finalBytes)` on live - the one and only live mutation; (4) integrity_check the now-live db. On any post-swap failure, live is restored from the backup (`restoreLiveFromBackup`); the backup is deleted only after success/verified-restore. `overwriteDatabaseFile` always gets an `ArrayBuffer` (read via `getDatabaseFile().arrayBuffer()`) - structured-cloning a File/Blob across the worker boundary triggered DataCloneError. The dump may come from a DIFFERENT account, so any `user_id` column is REWRITTEN to the current session's id on every shared-table row (`local_migrations` keeps final's own cursor; the grafted live-only tables have no user_id column). `LOCAL_ONLY_TABLES` (local_migrations, local_pending_tasks, tokenizers) are not copied from the dump. Returns `{imported, skipped, tables, skippedByTable}` for the toast. A crash MID-SWAP (corrupt live) is healed on next open by `recoverPendingImport` (called from `openClient` in `client.ts` before `openMigratedSql`): if a backup orphan exists it keeps live when intact, else restores from backup, then deletes the orphan; `isRecoverable` also matches `SQLITE_CORRUPT`/`SQLITE_NOTADB`/"file is not a database". (The old guest->user auto-migration and the `copyAllTables` salvage helper were removed; cross-account transfer is this manual import or the local export/import in `data/transfer/`.)

## Pending-task queue (the only deferred-work surface)

The Turso mirror sync was removed. What remains is a small local outbox in a
single file, `src/lib/db/client/outbox/pending/queue.ts`, driving ONE task type,
`logEnrich`. The table shape leaves room for a second task type later, but the
code is deliberately not a generic engine (no handler registry, no coalesce/
onRetry/onExhausted hooks); add a `taskType` branch in `queue.ts` if sync returns.

- `pending/queue.ts`: `enqueueLogEnrich(userId, msgId, requestId)` upserts a row by `(taskType, kind, id)`, resetting backoff and bumping `seq`; `drainPending` (FIFO + backoff, deletes a row only if its `seq` is unchanged so a mid-drain re-enqueue survives, dead-letters at `MAX_ATTEMPTS=5`); `drain(userId)` wraps it in an in-tab single-flight `Map` (overlapping debounce + periodic-tick triggers share one drain instead of racing the sqlocal transactionMutex); `drainSoon` is the 250ms-debounced post-enqueue drain. NO cross-tab lock on the drain: a duplicate enrich from another tab is harmless and rare. `drain` calls `enrichRequestLogFromUpstream` (`outbox/log-enrich.ts`) to pull new-api's authoritative cost/tokens/channel for the finished request and patch the LOCAL `request_logs` row, retrying on not-yet-logged. Reload-durable: a pending row survives a refresh.
- `src/hooks/ai/use-pending-drain-scheduler.ts`: periodic + focus/online `drain` tick, mounted in `ChatRuntimeProvider`. Happy path is `drainSoon` right after `enqueueLogEnrich` at stream finish (`chat-history-adapter.ts`).
- `outbox/resource-lock.ts` (Web Locks) is NOT used by the queue anymore; its callers are the per-tab pool ownership in `client.ts` (`acquireLock` fast path + `acquireLockWaiting` handover wait) and the per-conversation stream lock in `chat-runtime-provider.tsx` (blocks two tabs streaming the same conversation, with a user-facing "locked in other tab" toast; the browser auto-releases when the holding tab dies).

`outbox/resource-lock.ts` (generic `navigator.locks` cross-tab lock) and `outbox/log-enrich.ts` are the only other files in the `outbox/` folder (renamed from `sync/`). There is NO mirror, hydrator, reconcile, build-payload, apply-bundle, or server `/sync` route anymore.

## Rendering model

Every route is dynamic (`ƒ` in the build output); only `robots.txt`, `sitemap.xml`, the service
worker and `/en/offline` are static files. Nothing prerenders, `cacheComponents` is off, and there
are no `export const instant` or `use cache` directives left in `src/`. The one surviving
`generateStaticParams` is `sw-worker/[path]/route.ts`, which genuinely emits static SW assets.

There is also ZERO `<Suspense>` in `src/`, which is deliberate rather than an oversight. The
boundaries that existed were prerender ceremony: they let Next paint a static shell around a
request-bound hole, which is worthless when the shell itself is rendered per request. Removing them
was verified against home, models, rankings, status, settings, chat and image, plus a CLS trace on
the models page under a lazy (non-lucide) icon theme: 0.01, versus the 0.2 the old `icon.tsx`
fallback was written to prevent.

Consequences worth knowing before adding one back: a suspending client hook (`useSearchParams`,
`useQueryState`) or a `next/dynamic`/`React.lazy` chunk now suspends to the root, so a slow chunk
blanks the page instead of a subtree. If that shows up on a real connection, add ONE targeted
boundary at the component, do not restore the layout-level gates.

## Route groups (app directory)

404s: Next 16 never fires `[locale]/not-found.tsx` for `notFound()` calls bubbling out of child segments (the root-layout segment's boundary doesn't attach; the error boundary rendered instead). Each route group whose pages call `notFound()` therefore carries its own `not-found.tsx` ((navbar), (docs)) rendering the shared `NotFoundCard` (`src/components/elements/feedback/not-found-card.tsx`) inside its layout shell; `[locale]/not-found.tsx` stays for direct/unmatched cases. A new group that calls `notFound()` needs its own `not-found.tsx`.

Locale-prefixed groups under `src/app/[locale]/`:

- `(auth)`: login, register
- `(chat)`: main chat UI (`chat/`, with nested `cards/`, `presets/`, `[convId]/`). Layout mounts `ChatRuntimeProvider` (which also mounts the pending-task drain scheduler), plus SSR prefetch of auth/best-key. Pricing is deliberately NOT dehydrated here (nor on the homepage); the model selector/ticker fetch the lean pricing payload client-side after mount (see `models/pricing/` above).
- `(sidebar)`: dashboard, billing, settings, token, affiliate, logs. The layout IS the auth gate: it awaits the cookie-bound self lookup and `redirectToLogin()`s on an empty result, so it must stay a plain async layout (a Suspense wrapper would commit a 200 before the redirect could fire).
- `(navbar)`: marketing surface. Contains `(home)`, `pricing`, `models` (`[slug]`), `blog`, `rankings`, and nested `(legal)` (privacy, terms).
- `(docs)`: docs surface under `(docs)/docs/`. Every setup guide renders from ONE dynamic route `docs/[slug]/page.tsx` driven by the `SETUP_GUIDES` data array (`src/components/pages/docs/setup-guides.ts`). the page looks up the guide by slug (`getSetupGuide`, `notFound()` on miss) and renders `setup-guide-template.tsx` (hero, compat chips, steps, gotchas; recommended models come from `getCachedFreeChatModels(5)` at runtime, never hardcoded). Add a normal guide by adding one object to `SETUP_GUIDES` (no new route, no new file). Escape hatch: a guide with `customComponent` (`"cc-switch" | "claude-code"`) renders a bespoke body via the `BespokeBody` switch in `[slug]/page.tsx` instead of the template (bodies in `cli/cc-switch/` + `cli/claude-code/`). `DOCS_REGISTRY` (`src/i18n/registry.ts`) derives its entries from `SETUP_GUIDES`, so search/sitemap/llms.txt pick up new guides with no edit (plus one `GUIDE_DATES` entry in registry.ts for the publish date). Nav megamenu (`nav/navigation.ts`), docs sidebar (`docs-navigation.ts`), and the docs index all derive from `SETUP_GUIDES` too. No static per-guide routes remain. `fumadocs-core/toc` is the TOC helper only (not the doc framework).
- `(status)`: model status page (`status/`), backed by the `models/model-status` route
- `consent/`: OAuth consent flow (plain segment, requires session; not a route group)
- `offline/`: static SW offline fallback page (no auth/SQLocal)

Non-locale segments under `src/app/`:

- `(discovery)`: SEO + agent-discovery surface. 15 route handlers: static SEO (`humans.txt`, `llms.txt`, `openapi.json`, `robots.txt`) plus `.well-known/` (`agent-card.json` per A2A spec, `mcp.json`, `mcp/server-card.json`, `agent-skills/index.json`, `api-catalog`, `oauth-authorization-server`, `oauth-protected-resource`, `openid-configuration`, `ucp`, `http-message-signatures-directory`, `security.txt`).
- `api/[[...route]]`: Elysia BFF entrypoint
- `sqlocal/`: SQLocal/OPFS worker assets + the `/sqlocal/studio-css` route handler that serves the `@libsqlstudio/gui` stylesheet (with `:root` -> `:host` and `.dark` -> `:host(.dark)` rewrites for the Local DB Studio's Shadow DOM).

## Agent + Browser extensions

`src/components/provider/app/webmcp-provider.tsx` registers WebMCP tools on `navigator.modelContext` from `src/lib/config/webmcp-tools.ts` descriptors (`open_models_catalog`, `open_pricing`, `open_docs`, etc). Each tool returns `{path, target?, resultKey?}`; the provider handles navigation. Discoverable via `/.well-known/mcp.json` and `/.well-known/mcp/server-card.json`.

`src/components/elements/db/local-db-studio.tsx`: user-facing OPFS inspector embedding `@libsqlstudio/gui` in a Shadow DOM (so its CSS doesn't bleed). Actions: wipe (destroys SyncAccessHandle FIRST so `removeEntry` isn't no-op'd by the lock, then iterates root and removes everything), download (a `DownloadPopover` with three checkboxes `includeChats`/`includeRequestLogs`/`includeMedia` + a "export without chats" preset -> `downloadLocalDb(userId, filename, options)`), and import (releases the cached live handle, then `reconcileImport` builds a fresh current-schema replacement and atomically swaps it in with a backup-guarded single write, user_id remapped to this session; toasts an imported/skipped summary). Export is NON-DESTRUCTIVE: `downloadLocalDb` (`data/diagnostics/db-export.ts`) copies the live db into a SCRATCH (`-export.sqlite3`), deletes the excluded tables' rows on the scratch, VACUUMs, and streams the scratch file out - the live db and its `request_logs` are never touched. `streamFileToDisk` (`utils/client.ts`) uses `showSaveFilePicker` + `pipeTo` where available (no full-heap materialization), falling back to a blob-URL download on iOS. Forces full reload after destructive actions (wipe/import).

## Free-model race pattern

Centralized in `src/lib/ai/chat/free-model-race.ts` (`freeModelRace`, isomorphic + provider-injected: takes `generate` + `listFreeModels` instead of importing the server provider). It fires EVERY model `listFreeModels` returns concurrently and takes the first success, so that list must stay short: the server wiring passes the fixed `UTILITY_RACE_MODELS` trio, never the live free-model catalog (doing so cost ~172 upstream requests per title). Server wiring is `src/server/ai/chat/free-model-race-server.ts` (`serverFreeModelRaceDeps`); client wiring rides the default/custom `AssemblerDeps.runFreeModelRace`. Consumers: title generation (`title.service.ts`, server), web-search classification (`src/server/ai/chat/context/web-search.service.ts:needsWebSearch`), rolling-summary folding (`src/lib/ai/chat/context/memory.service.ts`). Free models are flaky individually but a 3-way race resolves fast and fails closed. Title generation calls `UTILITY_RACE_MODELS` directly rather than through `freeModelRace`.

## SSRF-safe remote fetch

`src/lib/config/safe-fetch.ts` (extracted from the removed `config/r2.ts`). Used by character-card import, web-bot-auth directory fetch, model-tester verify, model verify-proxy, and chat media fetch (`safeFetchBytes`/`safeFetchRaw`/`downloadGenerationBytes`/`verifyMagicBytes`). SSRF protection: blocked IPv4/IPv6 CIDR allowlist (loopback, link-local, RFC1918, CGNAT, carrier-grade NAT, broadcast). Hostname blocklist (`localhost`, `metadata.google.internal`, `metadata.goog`, `.internal` suffix). Port allowlist `[80, 443]`. Protocol allowlist `http/https`. Custom `undici` Agent with a `filteringLookup` DNS resolver that rejects non-public addresses at connect time. `redirect: "manual"` to close redirect-bypass. Download cap `MAX_DOWNLOAD_BYTES=50MB` (streamed with running total). Magic-byte verification via `file-type`; allowlist `image/*, video/*, audio/*, application/pdf`; declared content-type must match detected (category-level for media, exact for documents).

## Background work

- Caching is DATA-ONLY, in-module, and deliberately so. There is no framework-level render caching: `cacheComponents` is OFF, and `use cache`/`cacheLife`/`PUBLIC_CACHE` were all removed (2026-08-14). Component caching cost a double render on every request (Next attempts a prerender, hits request data, discards it, renders again), which is pure waste on an app where nearly every route reads cookies. Do not reintroduce `use cache` or `cacheComponents` to "speed things up"; it measurably did the opposite here.
- What remains, all plain `Map`+timestamp module state: pricing 5min (`pricing-snapshot.ts`, now also keeping the built `summary`), stats summary 5min (`ops/stats/stats.service.ts`, promise-cached so expiry bursts share one aggregate run), web-bot-auth directory 10min, benchmarks permaslug 30d, runware catalog search 30min. The badge layer caches NOTHING itself anymore: `getStats`/`getPricingData`/`findBadgeModel` derive from the stats + pricing-snapshot caches, so those two upstreams have exactly one cache each per pod. Cloudflare sits in front of the public BFF responses (purged by CI after deploy).
- Upstream GETs are NOT deduped across requests anymore. If gateway request volume becomes a problem, the fix is a wider in-module TTL, not `next: { revalidate }`. Should a URL-keyed fetch cache ever come back, it MUST pair with `ADMIN_HEADERS`: `customFetch` auto-attaches user cookies without explicit auth, and a URL-only cache key would serve one user's response to everyone.

## Discord reward amounts (docs)

The reward figures on `/docs/platform/discord-rewards` are NOT hardcoded and NOT in the locale
files. `getRewardAmounts(locale)` (`src/lib/config/rewards.ts`) fetches the Discord bot's
`GET /rewards` over the cluster network (`serverEnv.botInternalUrl`, default
`http://unorouter-bot:4000`, ClusterIP with no public ingress) on every render, so changing a
payout is a bot env change plus a bot restart - no site deploy, no translation edits.

- Amounts reach the copy as ICU placeholders (`{voteReward}`, `{levelTotal}`, ...) spread into the
  same values object `APP_VALUES` already uses. Messages precompile at build, so a typo'd
  placeholder FAILS THE BUILD rather than rendering wrong.
- Locale values carry the currency symbol and their own decimal convention; only the numeral is
  interpolated, formatted per locale via `Intl.NumberFormat`. Do not put `$` in the fetched value.
- `FALLBACK` in that file is a last-known-good safety net for when the bot is unreachable. It is
  NOT the place to change a reward; editing it changes nothing while the bot is healthy.
- The level table rows come from the same fetch. There are no reward screenshots: they were
  deleted because they silently went stale, and the prose covers both flows.

## Analytics

`src/lib/analytics.ts` is the canonical telemetry surface. Single `analytics` const groups events by feature (`auth/chat/billing/tokens/settings/navigation/affiliate/dashboard/logs/docs/rp/content`). Every event takes typed args and calls `posthog.capture(name, props)`. Components import as `analytics.<feature>.<event>(...)`. Add new events here; never call `posthog.capture` directly from a component.

Client posthog-js is NEVER statically imported (63KiB gzip would land in every page bundle). All client callers import the queue-buffered shim `src/lib/posthog-lazy.ts`; `instrumentation-client.ts` dynamically imports + inits posthog-js (prod, `NEXT_PUBLIC_POSTHOG_DISABLED` unset) and registers the instance, which flushes queued calls.

Server-side events go through `captureServerEvent` in `src/lib/posthog-server.ts` (prod-only, stitches distinctId from `ph_phc_*_posthog` cookie, falls back to `user-id`). Used by `media-stream.service.ts` (`chat_stream_started` for media generation). The default text path streams client-side through the proxy, so its lifecycle events are client posthog, not server.

`NEXT_PUBLIC_POSTHOG_DISABLED=true` (build-time, baked by Next) turns PostHog off entirely: `POSTHOG_DISABLED` in `src/lib/config/constants.ts` gates client init (`instrumentation-client.ts`), the provider (`posthog-provider.tsx`), server captures (`captureServerEvent`), and error reporting (`instrumentation.ts` `onRequestError`).

## User theme

`src/components/ui/theme/`: shadcn-variable theme customizer. `theme-store.ts` (`UserTheme`, `userThemeAtom` = atomWithStorage over `jotaiCookieStorage`, cookie loads after mount; the server never reads the theme cookie), `theme-build-css.ts` (`buildThemeCss` + `buildBackgroundCss`; background image is localStorage-only, painted on `body::before`). `[locale]/layout.tsx` ships a STATIC default-theme shell: default `themeDataAttrs` on `<html>`, default CSS in `<style id="user-theme">`, plus a pre-paint inline script that applies the cookie's data-attrs (style/menu/menuAccent/iconLibrary) before first paint; `UserThemeProvider` swaps in the full custom CSS at hydration (custom color palettes flash default until then). `theme-store-provider.tsx` and `theme-server.ts` were removed. Synced cross-device as the single-row `theme` sync kind (`userThemes` table).

## Imperative confirm

`src/components/ui/confirm.tsx` exports `confirm(options): Promise<boolean>` (replaces `window.confirm`). Backed by a single pending-request atom written through `chatStore`, so it's callable from any handler (event, mutation, hook) without context or prop drilling. A second `confirm()` resolves the pending one as `false` first. `ConfirmProvider` is mounted once near the providers root.

## Private routes / robots / sitemap

`src/i18n/routing.ts` exports `privateRoutes = { static, dynamicParents }` as the single source of truth for `robots.txt` Disallow rules and `sitemap.xml` exclusions. Add a new authenticated route here, not in two places.

`src/app/sitemap.ts` enumerates every locale x pathname, looks up timestamps from `getSeoTimestamps`, and derives model slugs from live pricing including offline/retired models (`getCachedPricing(true)`, i.e. new-api's `include_offline`). `:free` twins are self-canonical distinct pages (own `/models/[slug]` URL, own sitemap entry); `/models/[slug]` no longer redirects a `:free` twin to its base. `src/app/(discovery)/robots.txt/route.ts` emits end-anchored (`$` + `/`) Disallow pairs per locale per `privateRoutes` entry (a bare prefix once swallowed `/hi/login` via `/hi/log`) plus Allow lines for `privateRoutes.publicChildren` (public pages under a disallowed parent, e.g. `/chat/presets`).

## React Query client

`src/lib/react-query/client.ts` `getQueryClient()`: server uses `cache(makeQueryClient)` (per-request), browser uses a module-scoped singleton. Defaults: `refetchOnWindowFocus: false`, `staleTime: Infinity` (caches never auto-invalidate; mutations call `invalidateQueries` explicitly).

Cross-tab invalidation (`src/lib/react-query/cross-tab-invalidate.ts`): `broadcastInvalidate(keys)` posts query keys over a BroadcastChannel so a mutation in one tab refreshes the others; `subscribeInvalidate(qc)` (mounted once via `useEffect` in `query-provider.tsx`) receives them and calls `invalidateQueries`. `invalidateAndBroadcast(qc, keys)` does both the local invalidate and the broadcast (used by RP mutations + log enrichment).

## Cross-store API key bridge

`useApiKey` (`src/hooks/ui/use-api-key.ts`) reads `bestKey` via the billing token hook and mirrors the result into `apiKeyAtom` (cookie-backed `client-store`). The `client-store` cookie is what the server's `getApiKey(cookie)` reads. Net effect: a logged-in user's preferred token flows from server -> React Query -> Jotai cookie atom -> back to server on subsequent requests. The OS detection on mount writes into the same atom for code-snippet docs.
